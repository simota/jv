# Baseline of the Go implementation

Environment: Linux x86_64 (4 vCPU Xeon 2.1 GHz, 15 GiB RAM), Go 1.24.7,
`CGO_ENABLED=0 go build ./cmd/jv`.

## Existing tests

`go test ./...` — **PASS** (cli, diff, parser, pipe, tui; `cmd/jv` has no
tests). The fuzz target `FuzzParseMatchesEncodingJSON` was run only with
its seed corpus (as `go test` does).

## Behaviour captured as the reference

Rather than writing characterization tests in Go, the Go binary itself is
the oracle: `rust/tests/differential.rs` runs both binaries on the same
inputs and requires identical stdout, stderr, exit status and (with `2>&1`)
stream interleaving. Captured areas:

- all output formats, with and without color, `--sort-keys`, `-r`
- path queries (generated from real node paths plus malformed variations)
- syntax errors (generated by corrupting valid documents)
- `--diff` (files, stdin, `-p`, colored)
- flag parsing and usage errors, help text, input errors (missing file,
  directory, empty input, terminal stdin)
- shell completion (`completion`, `__complete`)
- large (3000-record) and deeply nested (up to 10001 levels) documents

TUI screens were captured by driving the Go viewer in a pseudo-terminal
(`rust/scripts/tui_smoke.py`), 16 scenarios.

Notable observed facts:

- `--color` defaults to `always`, so piped output is colored unless
  `-c never`/`-c auto` or `NO_COLOR` is used.
- Flag errors print the usage block to **stdout** (with a trailing blank
  line) and `Error: ...` to stderr.
- `jv -h a b c` prints help (help beats the argument-count check);
  `jv -h --bogus` fails (flag errors come first).
- At startup the Go viewer queries the terminal (OSC 11 background color,
  cursor position) and waits for answers.
- When stdout is closed early (`jv big.json | head`) the Go process is
  killed by SIGPIPE (shell status 141).

## Performance baseline

Measured with `rust/scripts/bench.py` (median of 5 runs after a warm-up,
peak RSS of the child), input generated by
`cargo run --release --example gen_bench_data` (250,000 records, 55 MB):

| case | Go time (s) | Go peak RSS (MiB) |
|---|---:|---:|
| pretty | 2.091 | 1134 |
| pretty + color | 3.153 | 1563 |
| compact | 1.620 | 945 |
| sort-keys | 2.362 | 1159 |
| flat | 2.592 | 1530 |
| typed | 2.855 | 1666 |
| schema | 1.173 | 636 |
| path `[*].address.city` | 1.200 | 680 |
| JSON Lines compact | 1.750 | 999 |
| wide object (200k keys) | 0.152 | 75 |
| diff (55 MB vs 55 MB) | 1.029 | 686 |
| startup (tiny input) | 0.002 | 14 |

Go binary size (`go build`, as in the release workflow): 6.1 MB.

## Suspected bugs in the Go version (recorded, not "fixed" silently)

1. **Numeric diff precision**: `numbersEqual` parses with `big.Float` at
   64-bit precision, so `1.00000000000000000001` and `1` compare equal.
2. **Completion descriptions variable**: cobra removes `__complete` from
   jv's root while completing, so `JV_COMPLETION_DESCRIPTIONS` is ignored
   for top-level completions (only `COBRA_COMPLETION_DESCRIPTIONS` works).
3. **Selected-line highlight** in the TUI stops at the first styled span
   (lipgloss re-styling text that already contains resets).
4. `Ctrl+C` does not quit while the search prompt is open (kept as is: it
   is plausible behaviour for a text field and harmless).

## Not verified

- Clipboard integration with real clipboard tools (no display/clipboard in
  the container); the OSC 52 sequence format is unit-tested.
- macOS and Windows behaviour (CI jobs added; not run locally).
